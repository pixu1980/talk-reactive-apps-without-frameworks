One checkbox, whole runtime

This walkthrough follows one real update in the demo: user checks the completed checkbox on a todo item. One logical field change travels through the runtime until the DOM shows the new state.

Store to DOM pipeline


DOM input
  -> model directive
  -> todo action
  -> proxy store write
  -> store:change event
  -> tickState signal
  -> computed signals and effects
  -> template parts
  -> DOM updates
Important detail: this demo does not create one signal per store field. Proxy store is source of truth. tickState is the bridge that tells the signal layer something changed.
