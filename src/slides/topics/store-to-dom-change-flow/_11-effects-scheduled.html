Step 10 - effects are scheduled, not run inline

`mountApp()` creates effects that read `tickState`. Each effect subscribes to the pulse and gets queued in a microtask when it changes.

App effects


effect(() => {
  tickState.get()
  syncDocumentPreferences(store)
})

effect(() => {
  tickState.get()
  render(App(), root)
  scheduleAppShellSizeSync(() => {
    syncAppShellSize({
      root,
      observedAppShell,
      setObservedAppShell: (value) => {
        observedAppShell = value
      },
      appShellResizeObserver,
    })
  })
})

Scheduler


addDependency(signal) {
  if (this.dependencies.has(signal)) return

  const unsubscribe = signal.subscribe(() => schedule(this))
  this.dependencies.set(signal, unsubscribe)
}

export function schedule(effect) {
  scheduled.add(effect)

  if (flushing) return

  flushing = true

  queueMicrotask(() => {
    try {
      while (scheduled.size > 0) {
        const batch = [...scheduled]
        scheduled.clear()

        for (const job of batch) {
          job.run()
        }
      }
    } finally {
      flushing = false
    }
  })
}
One store mutation can notify many subscribers, but app render effect still runs through one queued job.
